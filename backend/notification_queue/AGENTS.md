- Deploy-script rule: immediately after install, the deploy script MUST call `messaging_domain.set_notification_queue_canister(<notification_queue canister id>)` and `notification_queue.set_messaging_domain_canister(<messaging_domain canister id>)` — the chat notify fan-out hook is fail-closed while unset (messages send fine, no chat notifications enqueued), and record_chat_notify_batch only trusts recipient/mute lists from the configured messaging_domain principal (user callers may only fan out their own messages; their mute list is ignored).
- Deploy-script rule: when `ICP_PUSH_WORKER_SEED` (64-hex Ed25519 seed) is set, the deploy script MUST call `notification_queue.grant_worker(<principal derived from the seed>)` — push delivery (scripts/icp-push-deliver.mjs, run by the icp-push-deliver GitHub workflow) is fail-closed while the worker principal is ungranted. Device tokens live ON notification_queue (register_device_token caller-scoped; list_device_tokens/remove_device_tokens worker-gated); recover() resets ALL Processing items to Pending, so only run the worker serialized (workflow concurrency group) — never two workers at once.
- Deploy-script rule: immediately after install, the deploy script MUST call `notification_queue.set_club_domain_canister(<club_domain canister id>)` — app-admin gated get_push_delivery_health/cleanup_stale_device_tokens verify the caller against club_domain's app_admin role and fail-closed while unset.
- Scheduled chat messages (ICP) are delivered by notification_queue's transient 5-minute timer calling messaging_domain.deliver_scheduled_message (trusted only from the configured notification_queue; re-runs all send checks as the author). Needs the existing set_messaging_domain_canister / set_notification_queue_canister wiring; recurring items roll forward on notification_queue.
- Notification claim scans at most 200 rows with a transient rotating cursor in both modes; private delivery separately rechecks club/chat authority against its worker lease. Why: polling must not starve eligible rows and claim is not permission to send after revocation.
- Browser self-tests use expiring caller-owned rows, atomic worker claim and terminal no-retry settlement, never items/leases/recover or legacy device tokens; rekey revokes them. Why: a one-shot DEV test must not activate or interfere with recurring delivery.
- Native sender rollout covers only the TEST base queue and the LIVE base queue (LIVE reserves solely for its built-in recipient allowlist), default unconfigured; on-chain handover disables legacy claim/recover and native receipts remain on ICP, with unknown sends held. Why: server instances cannot coordinate safely using local state or replay uncertain sends.
