# Photo store rules

- Media: packed/roots stay fixtures; memory 13 keeps promises; tokens/free-only, paired revisions/buddies remain. Separate configured, physical and 80% payload caps; upgrades keep sizes. Sparse tests need actor upgrade/accounting checks; live needs approval. Why: capacity is not guaranteed space.
- Photo store capacity: app ceiling (uploadPolicy) < build `--max-stable-pages` (media mops.toml, 240 GiB) < Motoko 1.16.1 shared Region table (256 GiB). Never set the page cap at/above 256 GiB without a reviewed runtime. Why: the runtime has no aggregate block-table exhaustion guard.
- media_blob_store stores and serves only IBE ciphertext (no crypto, no key material on the canister; http_request is public by design — authorization happens at vetKey derivation on pii_access_control). Its contract in media_blob_store.did is fixed (frontend uploader + migration script pin it) — do not add/change methods without updating that file and the bindings. It has no initialize(): the deploy script MUST set the `GOVERNOR_PRINCIPAL` env var (deployer principal) before first use or delete_blob/abort override rights stay unset (fail-closed).
- Photo-store sharding: extra stores use shared source/migrations and distinct recipes/configs; never rebalance existing URLs. Admission uses uploadPolicy's effective heap-backed capacity, pending reservations and heap headroom. Additional free-club stores require authoritative cross-store quotas before activation. Why: a configured byte limit is not usable heap capacity, and per-store counters permit quota bypass.
- Per-club photo lock: pii_access_control.get_club_media_vetkey(club_id, transport) derives the vetKey for identity `clubmedia:<club_id>` U+001F `blob`, authorized live by club_domain.is_club_member (or governor); no stored record. club_media_lock_version() is the capability probe. Why: one paid derivation per member per club per session instead of one per photo.
- media_blob_store enforces free-plan media caps itself: begin_upload categorises clubs/<clubId>/ paths (vault/ segment, chat/files, chat|scheduled, else gallery; logos/sponsors/rewards/qr-codes/points-icon exempt), checks per-club 30-day-cycle counters and skips the cap when club_domain.get_club_subscription says Pro/trial. Why: browser-side checks are bypassable. Counters are per store canister.
- Free-club media retention (6 months): media_blob_store daily timer skips clubs whose Pro status is unknown; Supabase side runs via .github/workflows/free-media-retention.yml with service-role-only RPCs. Why: never delete on doubt; clients cannot delete storage safely.
- Media transfer inventories are governor-only consensus pages bounded to 200 scanned records, revision-bound across legacy/stable/pending/journal phases; persistent CAS club fences deny new uploads/deletion and pause retention, while existing uploads may settle. Storage inventory alone is not metadata reconciliation or permission to move encrypted clubs. Why: domain fences cannot stop staged/orphan blob writes or preserve vetKey authorities.
- Stable ciphertext storage is opt-in: empty additive Region/index migration, governor one-file hash-verified copy with drained uploads, then stable writes after all legacy files move. Dual reads and hash-pinned bounded HTTP streaming preserve URLs; reuse bounded power-of-two slots, never claim Region pages shrink. Update owner rekey, retention and delete for both formats. Snapshot before copying; old modules cannot read migrated records. Why: reduce persistent heap without an upgrade-time bulk copy or broken media access.
- Multi-Region media keeps original Store/Slice state as bank zero and adds lazy banks via a new migration; only the local rehearsal flag enables extra-bank writes. Never exceed the pinned RTS shared block-table limit or claim 500 GiB physical acceptance from address tests; test flags are not deployment flags. Why: bank count cannot overcome the runtime's aggregate Region ceiling.
- Original club-photo keys may use governor-only fenced revision-CAS membership-authority overrides, retained as abort tombstones; derive at the original PII canister through consensus membership and recheck authority/fence epochs after awaits. Reserve clubmedia identities and separator aliases from generic registration/import/derivation. Why: destination membership must not change cryptographic identity or permit a generic-record bypass; per-file grants remain a separate move gate.
- Frozen pre-authority source fixtures are hash-pinned and tested by test-media-legacy-upgrade; changes must also pass test-media-authority-replica for in-flight fences/authority changes, owner/reader/staff/guardian denial and key-name pinning. Why: upgrading the same new module twice cannot demonstrate old-schema ciphertext preservation.
- Media inventories are governor-only consensus pages capped at 200 scanned rows with mutation/fence revisions; include gallery cards, attachment registrations and trash, and reject unresolved scheduled media. Why: empty filtered pages cannot prove completion.
- Existing private blobs retain original PII records; retained grants check destination staff and private competition overrides use fenced governor CAS. Permanent deletion clears both overrides. Why: copied ciphertext and old role mirrors cannot preserve authorized private keys.
