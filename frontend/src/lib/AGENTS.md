- Retired URLs: App.tsx ParamRedirect, not 404.
- Pending sends are QueryClient-scoped; settle temp IDs from server acknowledgements, not photo presence. Why: avoid duplicates after navigation.
- Profile batches: get_profile for missing linked IDs.
- Share helpers prevent empty vault bubbles in both renderers. Schedule dates validate Date range, not just finiteness. Why: invalid dates crash calendars.

- Supabase club media accounting lists physical objects through clubMediaAllowance across gallery/vault/chat buckets with at most six concurrent page reads and no cached totals; related uploads share its same-device serialized allowance check. Why: serial whole-club scans stall chat attachments, while mirrors, stale totals and forwarded links must not double-count or bypass capacity; client checks are not server enforcement.
- Supabase Schedule reads use scheduleReadRepository with explicit relationship hints and a single missing-duty-column compatibility retry; retain every filter and propagate other failures. Why: older deployments lack the optional duty-team column and newer ones have multiple team relationships.
- Supabase media uses the caller's authenticated Storage upload callback after allowance checks, never purchase verification or elevated retries. Why: the environment-bound SDK preserves write options and Storage authorization; client quotas are not server enforcement.
- Storage POST listings are read-only and share the REST read deadline/resume registry; allowance preparation is bounded separately before writes and never advances after timeout. Why: SDK auth/body waits and frozen listing sockets otherwise strand the composer and its same-device upload queue; uncertain writes must never replay.
- Calendar exports share icsExport's mapping and club-zone UTC conversion; native exports use cached FileOpener files before Share and propagate failures to callers. Why: device zones, hostname links and swallowed failures make imports unreliable.
- Supabase profile saving uses profileSave compatibility for optional country and retries only a confirmed schema rejection; country UI requires the loaded field. Why: older schemas must save existing fields without masking permission or transport failures.
- Own-profile saves fall back to the plain identity_access set_profile only when read_secure_name_authority refuses with exactly "Secure personal-name saving is not released"; any other refusal stops the save. Avatar refs over 512 chars are omitted. Why: the canister enforces the release itself (refuses plain names once released), and fail-closed in the browser blocked every new secure-sign-in member on unreleased PROD.
- Canister `_headers`: never put Cache-Control on `/*` (rules merge); only HTML entry/sign-in files are no-cache and hashed `/assets/*` immutable. Startup stage timings go through lib/perfStages.ts and carry stage names only. Why: merged headers made assets "no-cache, immutable"; timing logs must not leak member data.
- Chat first pages try open_conversation_query, then the consensus open_conversation on any refusal; skip the quick read for 8s after this device writes to a chat and discard quick reads behind an already-seen latest_sequence. Chat-open timing lives in lib/chatOpenTrace (tap anchor, stage split, cold vs cached labels; ids never leave the device). Why: uncertified single-replica reads must never regress freshness or ordering.
- Internet Identity sign-out-on-failure (clearDeadIcpSession) requires getInternetIdentitySessionHealth() === "ended"; "unknown" retries. Missing-identity errors are IcpSessionRequiredError (thrown before any call). Edit-event keeps account+event-scoped `ignite_` sessionStorage drafts, populates once, and never auto-retries uncertain saves; uncertain recurring conversions block re-submit. Why: transient re-mint gaps bounced members to sign-in and discarded forms; series creation has no idempotency key.
- Edit-event supporting reads dispatch subscriptions by club, duties by event, assignment rosters by team/club and saved locations by club; roster profile enrichment uses readRelationshipProfiles with the same club. Propagate denied reads, never fall back to Supabase for II. Why: un-routed edit queries produced four blocked-transport warnings and hid duty assignments.
- Canister _redirects 404s missing /assets/* before the SPA fallback, and product-main installs chunkRecovery (one reload per build id, then surface the error). Why: index.html served as JS left old tabs blank after deploys.
- Chat cold-open diagnostics use bounded operation-name/timing-only tap ledgers; simultaneous page reads share only principal/full-target/page-bound in-flight promises, not new persistent caches. DM text maps before parallel enrichment, with page limits shared with existing warming. Why: remove duplicate waits without weakening destination authorization or expanding prefetch.
- DEV ICP push uses icpPushMode's fixed identity/directory boundary and separate native lifecycle/tap manager; registration remains commissioning-held until device ownership and gateway acceptance exist. Shared entry guards preserve legacy email/PROD behavior; ICP cleanup uses captured signers, never Firebase token deletion. Why: asynchronous refresh/sign-out must not cross accounts or backend modes.
- Competition-vault Storage writes are allowed only for competition managers into `clubs/<host>/competitions/<id>/<own uid>/<file>` (restrictive + permissive INSERT pair); updates stay service-only. Competition chats use the shared Attach sheet with From Vault disabled. Why: the old service-only write policy had no server uploader, so every competition chat/Vault file upload was refused.
- Native email alert taps are handled only by notificationLaunchHandler, started at the top of product-main; it skips ICP payloads (ignite_backend=icp-dev), which icpPushTap owns. Why: the initializer was dropped in the frontend migration, so taps opened the home page.
